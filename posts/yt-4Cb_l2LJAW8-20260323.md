## 📋 The Systematic Vibe Coding Approach

### Core Principle
> "Vibe coding isn't just typing a prompt and praying. It's about giving AI the **right context, constraints, and guardrails** before it writes a single line of code."

Người thường: prompt → code → bug → frustrated → start over.  
Systematic vibe coder: **plan → spec → rules → code → iterate → ship.**

---

### Step 1: Start With a Project Spec (PRD)

Before writing any code, create a **Product Requirements Document**:

```markdown
# Project: [App Name]

## Purpose
What does this app do in 1 sentence?

## User Stories
- As a [user], I want [feature] so that [benefit]

## Tech Stack
- Frontend: [React/Next.js/etc.]
- Backend: [Node/Python/etc.]
- Database: [Postgres/Supabase/etc.]

## Core Features (MVP)
1. Feature A — description
2. Feature B — description
3. Feature C — description

## Non-Functional Requirements
- Must work on mobile
- Must load under 3 seconds
- Authentication required
```

**Why this works:** AI viết code tốt hơn 10x khi nó biết trước toàn bộ scope. Không có spec, AI sẽ tự đoán architecture → sau này refactor lại rất khổ.

### Step 2: Set Up Custom Rules (`.cursorrules` / `.claud`)

Create rules files that constrain AI behavior:

```markdown
# .cursorrules

## Code Style
- Use TypeScript for all files
- Use functional components only
- Use Tailwind for styling, no CSS modules
- Use shadcn/ui components when available
- File naming: kebab-case

## Architecture
- Follow Next.js App Router conventions
- Keep server components by default, 'use client' only when needed
- API routes in /app/api/

## Rules
- NEVER delete existing functionality when adding new features
- Always add error handling
- Always make UI mobile-responsive
- Commit after each working feature
```

**Why this matters:** AI không nhớ gì giữa các conversations. Rules file = **persistent memory** — mỗi lần AI mở file mới, nó đọc rules trước.

### Step 3: Use AI For Scaffolding First

Don't ask AI to build everything at once. Start with:

1. **Generate project structure** — folders, config files, package.json
2. **Set up database schema** — tables, relations, types
3. **Build core UI layout** — navigation, pages, routing
4. **Then implement features one by one**

Mỗi bước: **chạy, test, commit, rồi mới tiếp.**

### Step 4: The Deepseek Advantage (Cost Efficiency)

| Model | Strength | Cost | When to Use |
|-------|----------|------|-------------|
| **Claude Sonnet** | Best code quality, architecture decisions | $$$ | Complex logic, refactoring |
| **Deepseek V3/R1** | Very good code, 95% of Claude quality | $ (1/30 price) | Routine coding, UI, CRUD |
| **GPT-4** | Good general, worse at code than Claude | $$ | Documentation, planning |

**Strategy:** Dùng Claude cho architecture + complex logic. Dùng Deepseek cho phần implementation (UI components, API routes, simple logic). **Tiết kiệm 80% chi phí.**

### Step 5: Debugging Workflow

When code breaks:

1. **Copy the full error message** — paste vào AI
2. **Include the full file** — không phải snippet nhỏ
3. **Describe what you expected vs what happened**
4. **Ask AI to explain before fixing** — "explain this error first, then propose a fix"

> "Don't just ask 'fix this'. Tell it: 'Here's the error, here's what I expected, here's the file. Explain what went wrong, then fix it without breaking anything else.'"

### Step 6: Iterative Refinement

Sau MVP:
- **UI Polish:** "Make this look more professional. Add spacing, animations, hover states."
- **Edge Cases:** "What happens if user submits empty form? Add validation."
- **Performance:** "This page loads slowly. Identify bottlenecks and optimize."
- **Testing:** "Write tests for the critical user paths."

### Step 7: Deployment

- **Vercel** cho Next.js — git push = auto deploy
- **Supabase** cho database — free tier generous
- **Cloudflare** cho static — unlimited bandwidth free

## 💡 Key Insights

### The 80/20 of Vibe Coding
1. **80% of your time should be planning**, 20% coding with AI
2. **The spec is more important than the prompt** — better spec = better code
3. **Custom rules prevent 90% of "AI broke everything" moments**
4. **Commit after every working state** — git is your safety net
5. **Don't fight AI's style** — adapt your architecture to what AI is good at (component-based, functional, typed)

### Common Mistakes
- ❌ Asking AI to "build me a full app" in one prompt
- ❌ Not having a rules file
- ❌ Not testing after each change
- ❌ Trying to use AI for optimization before getting basic functionality
- ❌ Expecting AI to remember context from 5 conversations ago

### When Vibe Coding Works Best
- ✅ Web apps (React, Next.js, Vue)
- ✅ CRUD applications
- ✅ Landing pages and marketing sites
- ✅ Prototypes and MVPs
- ✅ Internal tools
- ⚠️ Less suitable for: real-time systems, complex algorithms, embedded systems

---

## 🔑 Takeaways

1. **Spec first, code second** — spend 80% of time on planning
2. **Rules file = AI's persistent brain** — use .cursorrules or project docs
3. **Deepseek V3 = 95% of Claude at 1/30 the price** — use for bulk coding
4. **Scaffold → features → polish** — build incrementally, not all at once
5. **Git commit after every working state** — one prompt gone wrong shouldn't nuke your app
6. **Explain errors fully** — don't say "fix this", provide full context
7. **AI is your junior dev** — give it clear specs, review its output, iterate
